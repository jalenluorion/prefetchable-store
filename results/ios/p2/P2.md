rule is not changed here.

## 4-bit resident format (resident_q4; what the loader reads, for a calibrated drop-in)

File `<model>/.dmeng/resident_q4.dmres1.<first 12 hex of resident.safetensors' sha256>.bin` (Qwen3.6-35B-A3B:
`resident_q4.dmres1.a603e898ddee.bin`, 1,135,001,600 B, sha256 07d18ccfc459038a393cff498c4821c5133fc0be7d4ed17a91336cb4961c8ba6,
made by `ms_derive resident DIR --bits 4`, 251 matrices, 1,114 tensors). Loaded by `dm_open` with
`resident_bits = 4` (or `resident = <path>`); the app passes it on a phone below 5.0 GB of available memory at open.

- **Container: DMENGRES1** (the same as the 8-bit file). A text header padded to 1,048,576 B: first line
  `DMENGRES1 <header bytes>`, then lines `cfg <key> <value>` (the model's engine config exactly as in the 8-bit file,
  plus `cfg resident_bits 4`), then one line per tensor `t <name> <dtype> <offset> <nbytes> <ndim> <dims...>`, then
  `end`. Offsets are relative to the end of the header, each tensor 16,384-byte aligned; dtypes `u8`, `f16`, `f32`, `bf16`.
- **A 4-bit matrix `NAME`** [R rows (outputs), C columns (inputs), C % 64 == 0] is three tensors:
  `NAME.q4` u8 [R, C/2] (row-major; two codes per byte, element 2j in the low nibble of byte j, element 2j+1 in the
  high nibble), `NAME.s` f16 [R, C/64] (per row, per group of 64 consecutive inputs), `NAME.b` f16 [R, C/64].
  Dequantisation: `w[r, c] = code[r, c] * s[r, c/64] + b[r, c/64]`, codes 0..15 unsigned. (The `.q4` suffix selects
  the 4-bit kernels; the 8-bit file uses `.q`, [R, C] u8 codes, same scale / bias layout.)
- **Which tensors are 4-bit** (exactly the 8-bit file's affine set): per linear-attention layer L: `L.qkv`, `L.z`,
  `L.o`; per full-attention layer: `L.q`, `L.k`, `L.v`, `L.o`; every layer's shared expert `L.sg`, `L.su`, `L.sd`;
  the output head `head` [248320, 2048].
- **Kept exactly as in the 8-bit file**: `L.a`, `L.b` (in_proj_a / in_proj_b), `L.router` (the released router) and
  `L.shgate` (shared-expert gate) in bf16; norms (`L.ln_in`, `L.ln_post`, `L.gnorm`, `L.qn`, `L.kn`, `norm`; the
  `(1 + w)` ones stored as 1 + w), `L.conv` [channels, 4], `L.A_log`, `L.dt_bias` in f32. No embedding table: rows come
  from `embeddings.safetensors` (or the manifest's file) as for the 8-bit resident.
- **Today's quantiser** (`src/format/quant.h`, MLX's `affine_quantize`, the F16 rule: the bf16 weight cast to f16
  first; per group of 64 in float32: w_min = min(group), w_max = max(group, 0); scale = max((w_max - w_min) / 15, 1e-7)
  with the sign / edge rule of MLX; bias = the edge; code = min(round((w - bias) / scale), 15); scale and bias stored
  as f16). A calibrated set only has to keep the layout: any codes / scales / biases in these shapes load as is.
- **In moved-store.json terms**: a derived variant `{"id": "resident_q4", "from": ["resident.safetensors"],
  "engine_format": "dmres1", "bits": 4, "sha256": "07d18ccf...8ba6", "variant_of": "resident_q8", "optional": true,
  "for": "memory-limited devices (approximate: tokens differ from the 8-bit resident)"}`; a calibrated export would
  carry its own sha256 and, if it should coexist, its own id (e.g. `resident_q4c`, file `resident_q4c.dmres1.<hash>.bin`,
  loaded with `resident = <path>`).

**Answer: the OS keeps ~2.2-2.9 GB of clean store pages for the foreground app whatever dirty memory it holds, up to
3.3 GB** (the app's limit is 4.27 GB): the file cache is not taken from the app's budget. So the 8-bit resident loaded
as dirty memory (2.09 GB) costs the expert cache nothing, and **mapping the resident file-backed would make its 2.09 GB
compete with the experts for the same ~2.5 GB of file cache** (every token reads all of it: it would push out most expert
pages, or be re-read from the drive). Decision: the resident stays loaded (`res_memory_mode` PLAIN, the iOS default);
E4 (mapped resident) is a check of that prediction, not a candidate. The dirty budget left beside it (4.27 - 2.09 -
KV / prefix / scratch ~1.1 GB = ~1 GB) is better spent on a locked core of hot records (`-dmengCoreGB`) than left idle.

**B2: can the app drop pages it no longer wants?** (`-fileCacheTest drop`, 10:35, thermal fair: a target range of 64
records = 113 MB in layer 00's file and a control range of 64 records in layer 39's, both made resident, one method
applied to the target, mincore on both; then a re-read of the target):

| method | rc | call | target resident after (0 s / 1 s / 5 s) | control | re-read of the target |
|---|---|---|---|---|---|
| madvise MADV_DONTNEED | 0 | 0.54 ms | 1.00 / 1.00 / 1.00 | 1.00 | 0 page-ins |
| madvise MADV_FREE | 0 | 0.00 ms | 1.00 | 1.00 | 0 |
| madvise MADV_FREE_REUSABLE | EPERM | | 1.00 | 1.00 | 0 |
| madvise MADV_PAGEOUT (xnu value 10) | ENOTSUP | | 1.00 | 1.00 | 0 |
| **msync MS_INVALIDATE** | 0 | **3.69 ms (0.058 ms per record)** | **0.00 / 0.00 / 0.00** | **1.00** | **6,912 page-ins (= 64 x 108), 177 ms** |
| msync MS_KILLPAGES | 0 | 0.00 ms | 1.00 | 1.00 | 0 |
| msync MS_DEACTIVATE | 0 | 0.95 ms | 1.00 | 1.00 | 0 |
| munmap + mmap MAP_FIXED of the range | 0 | 0.56 ms | 1.00 | 1.00 | 0 |
| never touched while 6.0 GB of other records are swept; control re-touched every 0.5 s | | 12.8 s | **0.00** | **0.94** | |

**Answer: yes. `msync(MS_INVALIDATE)` on a clean read-only MAP_SHARED range drops exactly that range from the file
cache at once (0.058 ms per 1.77 MB record), leaving everything else** (the re-read pages in every page again: the
pages were really gone, not hidden). No madvise variant does anything on iOS 27.2 (the Mac's MADV_DONTNEED result in
P1 holds here too), nor do MS_KILLPAGES / MS_DEACTIVATE or unmapping. And the OS's reclaim follows use: a range not
touched while others stream goes first, a range touched every 0.5 s survives at 0.94. So **our policy can choose what
stays**: evict = MS_INVALIDATE the record, keep = touch it (the use already does). This makes EVICT.md's arrangement
B2 (one policy-managed tier over the whole file cache, hazard: 122 vs 139 MB/token for the OS's LRU at 3.3 GB on pitt)
buildable. Built on this branch: `file_evict_hint = 2` (store.cpp `drop()`; tool `--file-hint 2`, C API
`file_evict_hint`, app `-dmengEvictHint 2`), off by default; measured in E2b once the store is on the phone.
